1.1 The Rise of AI Reasoning

In 2024 and 2025, something changed in the world of artificial intelligence. Language models had already proven they could answer questions, write essays, summarize documents, and generate code. But they kept making surprisingly elementary mistakes on problems that required more than surface pattern matching — multi-step arithmetic, logical deductions, physics word problems, or anything demanding that the model work through a sequence of decisions before committing to a final answer.

The capability that closed this gap is called reasoning — the ability of a model to deliberate: to pause, think through intermediate steps, and check its own work before producing an answer. This book is about how reasoning is implemented in practice, and how you can build it yourself.

Why Reasoning Matters

Consider how an experienced software engineer approaches a complex bug. They do not guess the fix immediately. They reason:

  1. Reproduce the problem — narrow the conditions that cause the failure.

  2. Form a hypothesis — "the null pointer exception occurs because x."

  3. Test the hypothesis — add a log statement, run the test.

  4. Revise and repeat — if wrong, try the next hypothesis.

  5. Apply the fix — only after reasoning concludes, commit the change.

Early language models skipped all those intermediate steps. They jumped straight from the problem statement to a proposed answer — like a junior developer who looks at a stack trace for two seconds, types a fix, and pushes to production. A reasoning model, by contrast, produces a chain of thought before the final answer, mirroring the deliberate process above.

Note Throughout this book, we use the term reasoning specifically to mean explicit, multi-step, visible deliberation inside the model's output — not reasoning in the broad philosophical sense. When we say a model "reasons," we mean it generates intermediate thinking tokens before its final answer.

A Shift in the Field

Two developments accelerated interest in reasoning models. First, OpenAI released its o1 model in late 2024 — a model that generated long internal "thinking" passages invisible to users but which dramatically improved its accuracy on mathematical and coding benchmarks. Second, DeepSeek released R1 in early 2025, an open-weight model that matched or exceeded o1 on many benchmarks and whose training approach was published in detail. For the first time, the research community had a complete blueprint.

This book follows that blueprint — starting with a pre-trained open-source LLM (Qwen3) and layering reasoning capabilities on top, step by step, in code you can run and inspect on consumer hardware.

Tip — "From Scratch" Does Not Mean "From Random Weights" The phrase "from scratch" in this book's title means we implement every reasoning technique ourselves — we do not use a black-box API. However, we start from a pre-trained base LLM rather than training a neural network from random weights, which would require months of compute on thousands of GPUs.

1.2 What Is a Large Language Model?

Before we can understand reasoning, we need to understand language models themselves. This section builds a mental model from the ground up, deliberately connecting each concept to things a Java developer already knows.

1.2.1 Tokens: The Atoms of Language

A language model does not read characters. It reads tokens — variable-length chunks of text produced by a tokenizer. You can think of a tokenizer as a specialized String.split() operation with a very specific, learned vocabulary.

A typical modern tokenizer (such as the Byte-Pair Encoding algorithm, or BPE) starts from the Unicode byte alphabet and iteratively merges the most frequent adjacent pairs into new tokens. The result is a vocabulary of roughly 32,000–150,000 tokens that covers common English words, sub-word fragments, numbers, punctuation, and code symbols.

Example The phrase "Tokenization is useful!" might be split into tokens like: ["Token", "ization", " is", " useful", "!"]. Each token is mapped to an integer index: e.g., [1842, 2561, 374, 5505, 0]. Those integers are the only inputs the model ever sees.

Why sub-word tokens instead of whole words or single characters? Whole-word vocabularies explode in size (millions of words exist across languages) and cannot handle unseen words. Character-level models work but produce very long sequences, which are computationally expensive. Sub-word tokenization is a carefully engineered middle ground: rare words are split into familiar pieces, common words are kept intact.

Java Analogy — Tokens as enum Ordinals If you have ever mapped an enum to its ordinal for serialization, tokenization is conceptually similar. Each token string is assigned a unique integer. The model processes those integers, and the output is decoded back to strings. The vocabulary is the "enum registry" — a bidirectional map between string pieces and integer IDs.

1.2.2 The Neural Network: A Composition of Functions

A neural network is, at its core, a large mathematical function. Given an input vector x, it produces an output vector y:

$$ \mathbf{y} = f_{\theta}(\mathbf{x}) $$
The model function \( f_{\theta} \) maps input \( \mathbf{x} \) to output \( \mathbf{y} \). The subscript \( \theta \) (theta) denotes all learnable parameters.

For a language model, the input x is a sequence of token IDs, and the output y is a probability distribution over the vocabulary — a list of probabilities, one per token, summing to 1. The token with the highest probability is (usually) chosen as the next word in the sequence.

Internally, the function \( f_{\theta} \) is composed of many simpler functions stacked in layers. Each layer transforms the data slightly, and the transformations are controlled by learned numeric values called weights. The composition of all those layers is called a deep neural network (the "deep" refers to having many layers).

A single layer typically looks like this:

$$ \mathbf{h}^{(l+1)} = \sigma\!\left( \mathbf{W}^{(l)} \mathbf{h}^{(l)} + \mathbf{b}^{(l)} \right) $$
One layer of a neural network. \( \mathbf{h}^{(l)} \) is the layer's input (a vector); \( \mathbf{W}^{(l)} \) is the weight matrix; \( \mathbf{b}^{(l)} \) is the bias vector; \( \sigma \) is a nonlinear activation function (e.g., ReLU or GELU).

Do not be alarmed by the notation. In plain language: take the input, multiply it by a matrix of numbers (\( \mathbf{W} \)), add a small offset (\( \mathbf{b} \)), then apply a simple nonlinear function to introduce the ability to capture complex patterns. Repeat this for every layer. The entire model is nothing more — and nothing less — than this repeated pattern.

Java Analogy — Layers as Method Chains Think of each layer as a method that takes a double[] array, applies a matrix multiplication and an element-wise function, and returns a new double[]. The network is a chain of those method calls: layer3(layer2(layer1(embed(input)))). The "learning" phase finds the values for the matrices inside each layer.

Embeddings: Giving Tokens Meaning

Token IDs are arbitrary integers — the number 1842 doesn't mean anything mathematical. Before processing, each integer is converted to a high-dimensional embedding vector: a list of, say, 2048 floating-point numbers that represent the token's meaning in a learned geometric space.

$$ \mathbf{e}_i = \mathbf{E}[t_i] \in \mathbb{R}^{d_{\text{model}}} $$
Token \( t_i \) (an integer) is looked up in embedding matrix \( \mathbf{E} \) to produce a vector \( \mathbf{e}_i \) of dimension \( d_{\text{model}} \). For Qwen3-0.6B, \( d_{\text{model}} = 1024 \).

Embeddings capture semantic relationships. Words with similar meanings cluster nearby in this high-dimensional space. The famous example is:

$$ \text{emb}(\text{"king"}) - \text{emb}(\text{"man"}) + \text{emb}(\text{"woman"}) \approx \text{emb}(\text{"queen"}) $$
Vector arithmetic in embedding space captures analogical relationships.

1.2.3 Weights and Parameters: The Model's Knowledge

Every weight in the network is a single floating-point number. Together, these numbers encode everything the model has learned. A model described as having "7 billion parameters" has approximately 7 × 10⁹ such numbers stored in memory. At 16-bit (half) precision, that amounts to roughly 14 GB of data — which is why GPU memory capacity matters.

1.2.4 Pre-training: How the Model Learns Its World Model

Weights are not hand-coded. They are learned through a process called pre-training: exposing the model to an enormous corpus of text — hundreds of billions of tokens scraped from the web, books, code repositories, and scientific papers — and repeatedly adjusting the weights to make the model better at predicting the next token.

The adjustment procedure is called gradient descent. It works as follows:

  1. Forward pass — Feed a batch of text sequences through the model; for each position, compute the predicted probability distribution over the vocabulary.

  2. Compute loss — Compare predictions to the actual next tokens using cross-entropy loss: a single number measuring how wrong the model was.

  3. Backward pass (backpropagation) — Use the chain rule of calculus to compute, for every weight in the network, how much a small change in that weight would increase or decrease the loss.

  4. Update weights — Nudge every weight in the direction that reduces the loss by a tiny amount (the learning rate).

  5. Repeat — Billions of times, over trillions of tokens.

$$ \mathcal{L}_{\text{CE}} = -\frac{1}{N} \sum_{i=1}^{N} \log P_{\theta}(t_i \mid t_1, \ldots, t_{i-1}) $$
Cross-entropy loss for a sequence of \( N \) tokens. \( P_{\theta}(t_i \mid \cdots) \) is the probability the model assigned to the correct next token. The model learns to maximize this probability (minimize the negative log).

After pre-training on enough data, the model has implicitly learned grammar, facts, reasoning patterns, code syntax, and much more — all encoded in those billions of weights. This is why a pre-trained model can answer questions it was never explicitly taught to answer: it has built an internal world model by learning to predict text.

Important Misconception to Avoid A language model does not have a database of facts it looks up. It has no external memory. All knowledge is encoded as patterns in the weights, compressed and sometimes distorted. This is why models can "hallucinate" — confabulate plausible-sounding but incorrect facts. Understanding this limitation is crucial for understanding why we need additional techniques like reinforcement learning to improve reliability.

1.3 From Text Prediction to Language Understanding

A surprising philosophical point deserves attention before we go further: the only training signal a pre-trained LLM ever receives is predict the next token. No labels, no explicit reasoning examples, no human feedback. Yet from this single, simple objective, massively capable models emerge. How?

1.3.1 Next-Token Prediction as the Universal Pre-training Objective

To predict the next token well across all the domains in its training corpus, a model must acquire the underlying structure of those domains. Predicting the next word in a physics paper requires understanding physics. Predicting the next line of Java code requires understanding Java syntax and semantics. Predicting the continuation of a multi-step proof requires following logical deductions.

The task is an implicit compression challenge: the model must find the shortest description of all text it has seen — a description stored in its weights — that allows it to regenerate any part of that text. This enforces generalization rather than memorization of individual sentences.

Definition — Autoregressive Generation A model that generates output token-by-token, conditioning each new token on all previously generated tokens, is called autoregressive. The word comes from time-series analysis: each output is a "regression" on its own past. Virtually all modern LLMs, including Qwen3, GPT-4, and DeepSeek R1, are autoregressive Transformers.

1.3.2 The Attention Mechanism: How Context Is Integrated

A plain feed-forward network processes each token independently and cannot capture long-range dependencies — it cannot know that the pronoun "it" in the twentieth sentence refers to the noun introduced in the first. The attention mechanism, introduced in the 2017 paper Attention Is All You Need, solves this.

Attention allows every token in the sequence to "look at" every other token and decide how much to incorporate that other token's information when building its own representation. Mathematically, for a sequence of token vectors stacked into a matrix \( \mathbf{X} \), attention computes:

$$ \text{Attention}(\mathbf{Q}, \mathbf{K}, \mathbf{V}) = \text{softmax}\!\left( \frac{\mathbf{Q}\mathbf{K}^\top}{\sqrt{d_k}} \right) \mathbf{V} $$
Scaled dot-product attention. Queries \( \mathbf{Q} \), keys \( \mathbf{K} \), and values \( \mathbf{V} \) are linear projections of the input. The \( \sqrt{d_k} \) scaling prevents numerical instability with large dimensions.

Intuitively: each token asks a query ("what am I looking for?"), every other token presents a key ("here is what I offer"), and the dot product between them produces a score (how relevant is that token to me?). After softmax normalization, these scores become weights applied to the values (the actual information to incorporate).

The result: each token's representation is a weighted blend of the representations of all other tokens in the context, where the weights reflect learned relevance — not fixed positional rules.

1.3.3 The Context Window: Memory Limits and Their Consequences

Attention is applied over the entire sequence simultaneously, but the sequence has a maximum length called the context window (or context length). Tokens beyond this limit are simply not visible to the model. For Qwen3 models, the context window is 32,768 tokens (approximately 24,000 words of English text).

The context window is the model's entire working memory. Everything relevant to generating the current token must fit within it: the user's question, any prior conversation, retrieved documents, and the model's own generated reasoning trace. This constraint shapes many practical decisions — including how we structure long thinking chains in reasoning models.

Computational Cost of Attention The attention mechanism has a computational cost that grows quadratically with sequence length — \( O(n^2) \) in both time and memory, where \( n \) is the number of tokens. Doubling the context length quadruples the memory. This is why very long contexts require specialized hardware or algorithmic improvements (e.g., FlashAttention).

1.4 What Makes a Model "Reason"?

We now have a working definition of a language model. But we have not yet explained what distinguishes a reasoning model from a plain language model. This section makes that distinction precise.

1.4.1 The Shallow-Answer Problem

Consider the following question posed to a base language model:

Problem A bat and a ball together cost $1.10. The bat costs $1.00 more than the ball. How much does the ball cost?

The intuitive answer — and the answer many base LLMs give — is $0.10. But this is wrong. If the ball costs $0.10 and the bat costs $1.00 more, the bat costs $1.10, making the total $1.20, not $1.10. The correct answer is $0.05.

This is the classic bat-and-ball problem from behavioral economics, where it is used to demonstrate System 1 thinking (fast, intuitive, often wrong) versus System 2 thinking (slow, deliberate, careful). A base language model that responds with the first plausible-sounding token sequence is exhibiting System 1 behavior. A reasoning model forces System 2 behavior.

More concretely, setting up the equations reveals the error:

$$ \begin{aligned} \text{Let } b &= \text{price of ball}, \quad \text{bat} = b + 1.00 \\ b + (b + 1.00) &= 1.10 \\ 2b &= 0.10 \\ b &= 0.05 \end{aligned} $$
The correct solution requires setting up and solving a simple system of equations — a step-by-step process, not an immediate pattern match.

1.4.2 Chain of Thought: Deliberation in Text

The key insight behind reasoning models is deceptively simple: if we ask the model to write out its thinking before giving a final answer, it makes fewer mistakes.

This technique is called chain-of-thought (CoT) prompting. Instead of:

Standard (direct-answer) prompt PROMPT 
Q: A bat and a ball together cost $1.10. The bat costs $1.00 more
   than the ball. How much does the ball cost?
A:

A chain-of-thought prompt encourages explicit reasoning:

Chain-of-thought prompt PROMPT 
Q: A bat and a ball together cost $1.10. The bat costs $1.00 more
   than the ball. How much does the ball cost?
   Think step by step.
A: Let me define variables. Let b = cost of ball in dollars.
   Then the bat costs b + 1.00 dollars.
   Together: b + (b + 1.00) = 1.10
   Simplify: 2b + 1.00 = 1.10
   Solve: 2b = 0.10, so b = 0.05
   The ball costs $0.05.

The phrase "Think step by step" triggers the model to generate intermediate reasoning tokens. Because the model conditions each new token on all previous tokens, generating the algebraic setup in the middle of the response forces the final answer to be consistent with that setup. The model cannot hallucinate a wrong answer if it has correctly worked out the algebra one step earlier — the attention mechanism makes the correct answer the most probable continuation.

Definition — Thinking Tokens In modern reasoning models (GPT-o1, DeepSeek R1, Qwen3 with thinking mode), the model generates a special block of text enclosed in tags such as <think>...</think> before the visible answer. This block contains the chain of thought and may span thousands of tokens. Users typically see only the final answer; the thinking trace is either hidden or shown as a collapsible section.

1.4.3 The DeepSeek R1 Breakthrough

The DeepSeek R1 model, published in January 2025, demonstrated something remarkable: a model could learn to reason — not by being fine-tuned on human-written reasoning examples, but by discovering reasoning strategies on its own through reinforcement learning. The model received a reward signal only for correct final answers (verifiable outputs like math solutions or code that passes tests). Through thousands of training steps, it spontaneously developed:

  • Long chains of thought before answering.
  • Self-correction — recognizing mid-chain that a previous step was wrong.
  • Exploration of multiple solution paths before committing.
  • Verification of answers against the problem statement.

These capabilities emerged without being programmed explicitly — purely from the reward pressure to produce correct answers. This is analogous to a software system converging on an efficient algorithm not because it was hard-coded, but because its tests passed only for correct implementations.

Key Insight Reasoning behavior is not a feature you add to a language model. It is a behavior the model learns because it is rewarded for correct, verifiable outcomes. The role of the researcher is to design the right reward signal — not to hand-craft the reasoning strategy.

1.5 Three Approaches to Building Reasoning Models

This book covers three distinct techniques for building reasoning models. They are not mutually exclusive — DeepSeek R1 used all three in sequence. The figure below shows how they relate:

1.5.1 Inference-Time Scaling

Inference-time scaling improves model performance by computing more during the prediction phase — generating longer responses, producing multiple candidate answers, or iteratively refining outputs — without changing any weights. The insight is that the model already has most of the knowledge it needs; it just needs more "thinking time" to apply it correctly.

This book covers two primary inference-time scaling strategies:

Strategy Idea When to Use
Best-of-N Sampling Generate N independent answers; select the best one using a verifier or majority vote. When you have a reliable verifier (math, code).
Self-Refinement Generate an initial answer, critique it, then produce an improved version. When the model can self-evaluate.

The performance gain from inference-time scaling follows a predictable curve: accuracy increases with more compute, but with diminishing returns. There is an optimal compute budget for any given task. Chapter 4 explores this in depth with experiments.

1.5.2 Reinforcement Learning with Verifiable Rewards (RLVR)

Reinforcement learning (RL) is a training paradigm in which an agent takes actions in an environment and receives rewards based on the outcome. Applied to language models:

RL Concept Language Model Equivalent
AgentThe language model
ActionGenerating the next token
EpisodeA complete response (from prompt to final token)
RewardA score given to the complete response (e.g., +1 if correct)
PolicyThe model's probability distribution over tokens
Policy updateGradient descent to make rewarded responses more likely

The specific algorithm used in this book is Group Relative Policy Optimization (GRPO), a variant of proximal policy optimization designed specifically for language models. It generates multiple responses for each prompt, computes their relative rewards, and updates the model to assign higher probability to better responses.

$$ \mathcal{L}_{\text{GRPO}} = -\mathbb{E}\!\left[ \sum_{t} \min\!\left( r_t(\theta) \hat{A}_t,\; \text{clip}(r_t(\theta), 1-\varepsilon, 1+\varepsilon)\hat{A}_t \right) \right] $$
The GRPO objective (simplified). \( r_t(\theta) \) is the probability ratio between the new and old policy at token \( t \); \( \hat{A}_t \) is the estimated advantage (how much better than average this response was); clipping keeps updates stable. Do not worry about this formula now — Chapter 6 derives it step by step.
Why "Verifiable" Rewards? RLVR specifically uses rewards for tasks where correctness can be verified automatically — mathematics (check the numerical answer), code (run unit tests), logic puzzles (check the solution). This avoids needing a separate "reward model" trained on human preference data, which is expensive and can be gamed. If the answer is provably right, the reward signal is clean and unambiguous.

1.5.3 Knowledge Distillation

Knowledge distillation is a technique for transferring the capabilities of a large (teacher) model into a smaller (student) model. Instead of training the student from scratch or using reinforcement learning, you fine-tune the student on text generated by the teacher.

For reasoning models, this means:

  1. Use a large, high-quality reasoning model (e.g., DeepSeek R1 671B or GPT-4o) as the teacher. Generate many question–reasoning-trace–answer triples.

  2. Fine-tune the small student model on those triples using standard supervised training (next-token prediction on the teacher's responses).

  3. The student learns to mimic the teacher's reasoning style, achieving near-teacher performance at a fraction of the parameter count and compute cost.

Distillation is highly effective when the teacher is much stronger than the student. DeepSeek demonstrated that a 7B-parameter model distilled from the 671B R1 model outperforms the non-distilled 7B model by a substantial margin.

Why Distillation Is Practical for Developers You do not need to own or run the teacher model yourself. You can call a commercial API (OpenRouter, OpenAI) to generate teacher outputs, then fine-tune your small student model locally. Chapter 8 walks through exactly this workflow.

1.6 The Qwen3 Base Model

1.6.2 Qwen3 Architecture at a Glance

Qwen3 is a decoder-only Transformer. This means it uses only the decoder portion of the original Transformer architecture (unlike encoder-decoder models like the original T5 or BERT variants). Decoder-only models are the dominant architecture for generative language models today (GPT, LLaMA, Mistral, Gemma, DeepSeek are all decoder-only).

1.8.1 Syntax and Structure

The most striking syntactic difference for a Java developer is that Python uses indentation to delimit blocks instead of braces. There are no semicolons, no mandatory type declarations, and no public static void main ceremony.

Java — class and method Java 
public class Greeter {
    private String name;

    public Greeter(String name) {
        this.name = name;
    }

    public String greet() {
        if (this.name.isEmpty()) {
            return "Hello, world!";
        } else {
            return "Hello, " + this.name + "!";
        }
    }
}
Python — equivalent class Python 
class Greeter:
    def __init__(self, name: str):
        self.name = name

    def greet(self) -> str:
        if not self.name:
            return "Hello, world!"
        else:
            return f"Hello, {self.name}!"

Notice the structural parallels: __init__ is the constructor, self is this, and the colon at the end of class, def, and if lines replaces the opening brace. The f"..." syntax is a formatted string — equivalent to Java's String.format() or + name + "!" concatenation.

Virtually every numerical operation in this book uses either NumPy (for CPU array math) or PyTorch (for GPU-accelerated tensor operations). If you have never used these, think of them as libraries providing a type that is roughly equivalent to a multi-dimensional double[][] in Java — but with broadcasting (element-wise operations between arrays of compatible shapes), automatic differentiation, and GPU dispatch built in.

                    [0.3, 0.6]])   # shape: (3, 2)

# Element-wise operations broadcast automatically
biases = np.array([0.1, -0.1, 0.0])   # shape: (3,)
x = np.array([1.0, 2.0])              # shape: (2,)

# Matrix-vector product: equivalent to W·x + b
output = weights @ x + biases         # shape: (3,)
print(output)   # array([1.80, 0.60, 1.50])
Java Analogy — NumPy Array vs double[][] In Java, computing W * x + b for matrices and vectors requires nested loops. NumPy eliminates the loops entirely: the @ operator performs matrix multiplication, and arithmetic operators apply element-wise with automatic shape broadcasting. Under the hood, NumPy calls highly optimized BLAS/LAPACK routines — far faster than equivalent Java loops.
PyTorch — tensors on GPU Python / PyTorch 
import torch

# Create a tensor (NumPy array on steroids)
x = torch.tensor([1.0, 2.0, 3.0])

# Move to GPU (if available) — NumPy cannot do this
device = "cuda" if torch.cuda.is_available() else "cpu"
x = x.to(device)

# PyTorch automatically builds a computation graph
# enabling backpropagation (gradient computation)
x = torch.tensor([2.0], requires_grad=True)
y = x ** 2 + 3 * x + 1           # y = 4 + 6 + 1 = 11
y.backward()                       # compute dy/dx
print(x.grad)                      # tensor([7.]) — dy/dx = 2x+3 at x=2

The requires_grad=True flag tells PyTorch to track operations on that tensor so it can automatically compute derivatives — this is autograd, the engine behind backpropagation. You do not need to implement gradient formulas by hand; PyTorch does it automatically using the chain rule.

Summary

Chapter 1 Summary

  • A large language model (LLM) is a neural network that generates text by predicting the next token in a sequence. It is trained on massive text corpora using gradient descent to minimize cross-entropy loss.
  • Tokens are sub-word chunks mapped to integers. Embeddings are high-dimensional vectors that represent token meaning. Weights are all the learnable numbers in the network, collectively encoding its world model.
  • The attention mechanism allows every token to selectively incorporate information from every other token in the context, enabling the model to track long-range dependencies in language.
  • A reasoning model generates explicit intermediate steps — a chain of thought — before its final answer. This forces the model into deliberate, sequential reasoning rather than immediate pattern matching.
  • The DeepSeek R1 model demonstrated that reasoning behavior can emerge spontaneously through reinforcement learning from correct answers, without requiring hand-written reasoning examples.
  • This book covers three approaches to building reasoning models: inference-time scaling (compute more at inference), RLVR (train with verifiable rewards), and distillation (learn from a teacher model).
  • The Qwen3 model family is the base LLM for all experiments. Its open weights, small variants (0.6B–1.7B), and native thinking mode make it ideal for educational use on consumer hardware.
  • For Java developers, Python's core syntax is straightforward to learn. The most important libraries are NumPy (array math) and PyTorch (GPU-accelerated tensors and automatic differentiation).

Key Terms

Token
A variable-length sub-word unit of text, mapped to an integer ID by the tokenizer.
Embedding
A dense, real-valued vector representation of a token, encoding its meaning in high-dimensional space.
Weight / Parameter
A single learnable floating-point number inside the neural network. Collectively they encode the model's knowledge.
Pre-training
Large-scale training on text data using next-token prediction, producing a general-purpose base model.
Gradient Descent
The optimization algorithm that iteratively adjusts weights to minimize the loss function.
Cross-Entropy Loss
The training objective: negative log-probability of the correct next token.
Attention Mechanism
A layer that lets each token attend to (weight and incorporate) representations of all other tokens.
Context Window
The maximum number of tokens visible to the model in one forward pass — its working memory.
Autoregressive
Generating output one token at a time, conditioning each token on all previously generated tokens.
Chain of Thought (CoT)
Generating intermediate reasoning steps before a final answer, improving accuracy on multi-step tasks.
Reasoning Model
An LLM fine-tuned or prompted to produce explicit thinking traces before its answer.
Inference-Time Scaling
Improving quality by generating more tokens or candidates at inference time, without changing weights.
Reinforcement Learning (RL)
A training paradigm where an agent learns by receiving rewards for correct actions.
GRPO
Group Relative Policy Optimization — the RL algorithm used in this book to train reasoning models.
RLVR
Reinforcement Learning with Verifiable Rewards — RL using automated correctness checks as the reward signal.
Knowledge Distillation
Training a small student model on outputs generated by a large teacher model.
Decoder-Only Transformer
A transformer architecture that generates output autoregressively; the dominant design for modern LLMs.
Qwen3
The open-weight LLM family (by Alibaba) used as the base model throughout this book.
